# folio

大学生向けの資料・過去問管理Webアプリ。フォルダ整理、検索、お気に入り、PDF閲覧、手書き・テキストメモ、暗記マーカーを備えています。

## Android / iOS版

`android/`と`ios/`にネイティブプロジェクトを追加しました。PDF編集・フォルダ管理をアプリに同梱し、端末の保存画面に対応します。Android 10以上（WebView 120以上）・iOS 16以上を対象としています。

```sh
npm run mobile:sync
npm run android:build  # artifacts/folio-android-debug.apk
npm run ios:open      # macOS / Xcodeが必要
```

セットアップ、署名、変換サーバー接続、実機確認事項は [モバイル版の手順](docs/MOBILE.md) を参照してください。Webブラウザとネイティブアプリの資料は別の保存領域です。

## 起動（アプリを開く）

プロジェクトのフォルダーで、次のコマンドを実行します。Node.js 22以降が必要です。

```sh
npm install
# この環境では準備済み。Linuxで初めてWord変換を使うときに実行
npm run setup:office
npm run dev
```

**http://localhost:5173 を開いてください。起動したターミナルは開いたままにします。** PCやターミナルを再起動した後は、もう一度`npm run dev`が必要です。別の端末でこのURLを開いても、このPCのアプリには接続しません。

`npm run dev`は画面（5173）と変換API（3001）を一緒に起動します。5173番ポートを使えない場合はエラーを表示し、別のポートへ勝手に切り替えません。資料追加画面に「Word・PowerPoint変換：利用可能」と表示されれば、Word文書から実際のPDF生成まで確認済みです。

### Word変換エンジン

`npm run setup:office`はUbuntu/Debian系Linux向けです。apt-get、dpkg-deb、dpkg-architecture、Cコンパイラ（cc）を利用し、LibreOfficeと日本語フォントを`.runtime/office`へ配置します。最初のセットアップ時にダウンロードが必要です。設定はプロジェクト内に保持し、`/tmp`や一時的な環境変数には依存しません。

Windows/macOSではLibreOfficeをインストールしてください。標準のインストール場所を検出します。別の場所の場合は`LIBREOFFICE_BIN`を指定できます。この環境で通常起動する際の指定は不要です。

起動できてもPDF生成に失敗する構成を検出するため、`/api/health`ではバージョン確認に加えてサンプルDOCXを実変換します。Wordの変換に失敗した場合、資料追加画面にエラーメッセージを残します。

### ビルド版・Docker

```sh
npm run build
npm start
# http://localhost:3001 を開く（画面とAPIを配信）
```

```sh
docker build -t folio .
docker run --rm -p 127.0.0.1:3001:3001 --memory=2g --cpus=2 folio
```

DockerにはLibreOfficeと日本語フォントが含まれます。ビルド元の`.runtime`はコピーしません。

## ファイルの追加

PDF、JPG/JPEG、PNG、WebP、Word（DOC/DOCX）、PowerPoint（PPT/PPTX）、Excel（XLS/XLSX）に対応します。入力上限は50 MB、画像は4,000万画素です。

PDFは端末に直接保存します。その他のファイルは`POST /api/convert`へmultipartの`file`フィールドで送信し、サーバーが生成したPDFを受け取って端末に保存します。Office変換はリクエストごとの一時ディレクトリと専用プロファイルで実行し、マクロを無効化します。変換の同時実行は2件、Office変換のタイムアウトは60秒です。処理終了時に一時ファイルを削除します。変換の失敗時には資料を登録しません。

Officeのレイアウトはサーバーのフォント・LibreOfficeの互換性に依存します。パスワード付きファイルは未対応です。

## フォルダで資料を管理

「すべての資料」がファイル管理画面です。一覧・グリッド表示、PDFサムネイル、更新日・サイズ表示、名前／更新日時／サイズ順の並び替えに対応します。「資料を追加」は現在開いているフォルダへPDFを追加します。

- 「新しいフォルダ」で名前を入力して作成します。階層数に固定の上限はありません。
- フォルダ名を押すと開き、パンくずの「ホーム」や上位フォルダ名で戻れます。
- 右クリック、タッチでの長押し、各項目の「…」から、開く・名前変更・移動・複製・削除を選択できます。選択後の操作ボタン、Enter／F2／Deleteキーも使えます。
- 移動ダイアログで移動先を開いて確定します。PCではフォルダやパンくずへのドラッグ＆ドロップも使えます。自分自身・自分の配下への移動は禁止します。
- ファイルの名前変更では拡張子を固定します。同じフォルダ内の同名項目は、大文字小文字・Unicodeの表記差も考慮して拒否します。取り込み・複製時は連番を付け、既存項目を上書きしません。
- ファイル・フォルダの複製は配下の資料・注釈・下書きも新しいIDで複製します。コピー時点の編集を引き継ぎ、それ以降の編集・保存・削除は元とコピーで独立しています。コピーに未確定の下書きがある場合も復元確認を表示します。削除前に確認を表示し、フォルダ削除では配下のPDF本体・注釈・下書きも一緒に削除します。

## 新しいメモとホーム

サイドバー上部は「ホーム」「すべての資料」「お気に入り」「新しいメモ」です。「新しいメモ」でA4縦の白紙PDFを作成し、そのまま手書きできます。資料フォルダを開いている場合はそのフォルダ内に、それ以外ではホーム直下に作成します。同名の場合は連番を付けます。名前変更・移動・保存は他のPDFと共通です。

ホームの「マイメモ」には、白紙から作成した手書きメモとテキストメモのある資料を表示します。「すべて見る」で一覧を開けます。科目や過去問・ノートなどの固定分類・絞り込みはなくし、すべての資料をユーザーのフォルダ構成で整理します。旧データの分類情報は互換性のため保持しますが表示・絞り込みには使いません。

## PDF編集と3種類の保存

PDF.jsのcanvas上にannotation canvasを重ね、Pointer Eventsで手書きを入力します。色・太さ・暗記マーカーの不透明度を変更できます。暗記モードは`memorize`の線だけを黒・不透明にし、通常のペン線は変更しません。

「消しゴム」は、なぞった手書き線を線単位で削除します。1回の操作をUndo／Redoでき、消去結果も下書きに自動退避します。元PDFに含まれる文字・画像や、②③で埋め込み済みの線は消せません。

保存画面の「ファイル名」で保存時の名前を変更できます（.pdfは固定）。①②は資料IDを維持したまま名前を変更し、③は入力名でコピーを作成します。同名コピーは連番を付け、①②の同名衝突はエラーとして保存を止めます。外部保存ではダウンロード名だけが変わり、アプリ内の名前は変更しません。

右上の「保存」から「アプリ内」を選び、保存先フォルダを開いて確定方法を選びます。①②では資料IDを維持したまま選択フォルダに移動し、③では選択フォルダに新しい資料を作成します。

| 方法 | 保存結果 | 再度開いたとき |
| --- | --- | --- |
| ① 変更分だけアプリに保存 | 元PDFを維持して差分・メモを保存 | 元PDFと差分を自動合成。暗記切り替えと追加編集が可能 |
| ② 管理中のPDFに上書き | 手書きを埋め込んだPDFでアプリ内のファイルを置き換え | 埋め込み済みPDFを表示。適用済み差分はクリア |
| ③ 編集済みコピーを作成 | 元の資料を残し、新しいPDFをライブラリに追加 | コピーを開く。元資料は直前の確定状態を維持 |

②③は元PDFの文字・ページ内容を保持し、透明画像の手書きレイヤーを追加します。回転・CropBoxにも追従します。保存時の暗記モードに関係なく通常の色と不透明度で埋め込みます。埋め込んだ線は独立したストロークではなくなり、線の再編集・暗記切り替えはできません。テキストメモはアプリに保存し、PDF本体には埋め込みません。

「上書き」はアプリが管理するPDFの置き換えです。ブラウザで最初に選んだ端末上のファイルを直接変更するものではありません。ダウンロードは管理中のPDF本体を返し、未確定の変更や①の差分は含めません。編集を含むPDFが必要な場合は「保存」→「アプリ外のフォルダ」を使うか、②③で確定してからダウンロードしてください。

### アプリ外のフォルダに保存

「保存」→「アプリ外のフォルダ」で、現在の手書きを埋め込んだPDFを先に生成し、生成したデータをPDF.jsで再読み込みして全ページの描画命令を検証します。検証完了後に保存ボタンが有効になります。PDF生成に失敗しても、保存先に空ファイルを作らない流れです。書き出しではオブジェクトストリームを使わない形式で保存します。外部保存のボタン表示は「保存先を選んでPDFを保存」に統一し、対応ブラウザでも編集済みPDFをダウンロードする動作を既定とします。別の「編集済みPDFをダウンロード」ボタンは表示しません。保存場所はブラウザの設定に従い、毎回保存先を指定する場合はブラウザ側でダウンロード前に保存場所を確認する設定にしてください。

外部ファイル名はOSで使えない文字・予約名・長さを調整します（アプリ内の資料名は変更しません）。成功時は過去のエラーを消去し、生成・書き込みに失敗した場合にエラーを表示します。

外部への書き出しはアプリ内の元PDF・確定済み差分・下書きを変更しません。キャンセルや書き込みエラーでも下書きを保持します。外部保存後も次回の起動では未確定の下書きの復元確認が出ます。暗記マーカーは通常時の色で埋め込み、テキストメモはPDFに含めません。

## 自動退避と復元確認

確定済みの差分と、未保存の下書きを分けています。編集中の手書き（描画途中も含む）とテキストメモを、編集のたびに端末のIndexedDBに退避します。同時にlocalStorageへ同期的な復旧用記録を書き込み、未完了のIndexedDB書き込みを補います。終了イベントだけには依存しません。

アプリ再起動時には前回開いていたPDFを開き、下書きがあれば「復元する／破棄して開く」を表示します。選択するまでは変更を反映しません。確定済みの①の差分は確認なしで自動表示します。保存や破棄が成功すると下書きを消去します。PDFの版が変わっている下書きは誤適用を避けるため復元を無効にします。

IndexedDBの1トランザクションで、PDF・差分・資料一覧・下書きの削除をまとめて確定します。ブラウザのストレージ消去、容量不足、OSの強制終了直前の未完了書き込みなどまで完全に保証するものではありません。保存エラーは画面に表示します。Undo／Redoの操作履歴はビューア内のセッション単位です。

## 保存形式

IndexedDB `folio-pdf` v3:

- `files`: 資料ID → PDF Blob
- `annotations`: 資料ID → 確定済み差分 `{version, coordinateSpace, revision, pages}`
- `drafts`: 資料ID → `{version, baseRevision, updatedAt, pages, note}`
- `entries`: IDを主キーとするファイル・フォルダのノード。`parentId`インデックスあり
- `library`: `treeVersion` → 移行済みマーカー、`docs` → 既存画面向けのファイル一覧（互換用）

ノードの共通項目は `{id, name, type: 'file' | 'folder', parentId, createdAt, updatedAt}` です。ホーム直下の`parentId`は`null`、日時はISO形式です。ファイルには`mimeType, sizeBytes, originalName, storage: {provider, key}`などを追加します。従来の資料種別（講義資料・過去問など）は`category`に保持します。パスは親IDから表示時に組み立て、名前変更や移動でPDF・注釈のキーを変えません。

`FileExplorer.jsx`と`FolderPicker.jsx`がUI、`library-model.js`がストレージ非依存の階層・名前の規則、`library-repository.js`が保存処理の窓口、`storage.js`がIndexedDB実装です。階層変更・削除・複製はトランザクションでまとめて確定します。将来のクラウド対応ではリポジトリの実装を追加する設計で、現時点でクラウド接続や同期は実装していません。外部PDF書き出しは`external-storage.js`に分離しています。

`pages`はページ番号 → ストローク配列です。ストロークには`id, memorize, color, opacity, width, points`を保存します。pointsのx/yはPDFページの表示上の左上を原点とする0〜1の正規化座標で、widthはページ幅に対する比率です。既定の回転を適用したPDF.jsのviewportに対応します。

旧版のlocalStorageの資料一覧は初回に移行します。旧IndexedDB v2の資料一覧をホーム直下のノードへ移行し、数値IDも変更せず、PDF・差分・下書きを維持します。一覧のJSON書き出しにはPDF本体や手書きは含まれません。

## 現在の範囲

端末内保存のWeb版と、Android／iOSのネイティブプロジェクトがあります。認証、クラウド同期、ストア配信、iOS／Android実機でのOSバージョン検証は未実施です。変換APIはローカル利用を前提とし、公開運用には認証、利用者別制限、変換プロセスのネットワーク・ファイルアクセス隔離が必要です。AI画面はテンプレートによるデモで、モデル接続・OCRは未実装です。課金機能は含めていません。

参考: [PDF.js](https://mozilla.github.io/pdf.js/examples/)、[Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)、[PDF-LIB](https://pdf-lib.js.org/docs/api/classes/pdfpage)、[LibreOfficeの起動オプション](https://help.libreoffice.org/latest/en-GB/text/shared/guide/start_parameters.html)。

外部保存API: [showSaveFilePicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)、[createWritable](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable)。OSネイティブダイアログおよびiOS／Android実機での確認は別途必要です。

Android / iOS のクラウドビルド・署名は [クラウドビルド手順](docs/CLOUD-BUILD.md) を参照してください。
